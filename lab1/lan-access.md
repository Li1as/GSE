# 局域网接入与浏览器任务检查

记录日期：2026-09-15。

## 已配置链路

- Windows WLAN：`<Windows局域网IP>`。
- WSL：`<WSL-IP>`，网页服务监听 `0.0.0.0:8765`。
- Windows portproxy：`<Windows局域网IP>:8765` → `<WSL-IP>:8765`。
- 防火墙规则 `GSE-Lab1-8765`：仅 WLAN 接口、本机上述地址、TCP 8765、远端 LocalSubnet 入站允许。未关闭防火墙或扩大其他端口权限。

从 Windows 访问 WLAN 地址验证：页面 HTTP 200，未带访问口令的 `/api/tasks` 返回 401。手机可访问 `http://<Windows局域网IP>:8765`，仍须输入原访问口令。此处保留初次检查记录；后续用户已确认手机连通，见第二阶段总结。

配置脚本为 [configure-lan.ps1](configure-lan.ps1)，需要 Windows 管理员权限。Wi-Fi 地址或 WSL 地址变化后应更新转发；脚本可传 `-ListenAddress` 和 `-WslAddress`，旧监听地址的规则需要先删除。脚本要求显式传入两个地址，没有机器专属默认值。

如需撤销，在管理员 PowerShell 执行：

```powershell
netsh interface portproxy delete v4tov4 listenaddress=<Windows局域网IP> listenport=8765
Remove-NetFirewallRule -Name GSE-Lab1-8765
```

## 当前真实浏览器任务检查

检查对象为用户目标“询问更多测试内容，提供我的基本学术信息”的邮件任务。状态为 needs_review，草稿数为 0，未发送邮件。用户决定与两次 task 范围事实补充均已持久化。

发现的业务问题：

1. 父任务初始计划将询问更多测试内容、未阅读附件、历史不完整都写为固定 blockers。当前只是请求对方提供更多内容，这些限制不应一律阻止询问性草稿。
2. 用户后来明确披露字段后，父任务仍使用原始事实查询，没有根据决定缩小范围。子任务额外索取博士研究方向及博士毕业时间，超出本次基本信息目标。
3. 学校名称已有证据，但“当前在读状态不能由历史简历证明”的限定让该子任务进入 needs_review；需要把事实限定与影响本次回答的实际冲突区分开。
4. 其他学术信息子任务出现 DATA_ERROR。当前直接读取资料与别名正常，GPA 与编程语言检索有结果；现存异常记录不足以确定当时根因，不能认定资料文件现在损坏。

本次完成网络配置和只读诊断，没有删除阻塞项、改写测试任务、伪造用户决定或强制生成草稿。后续修复应处理决定变更后的计划收敛、可选字段、限定说明与真实阻塞的区别，以及更准确的错误分类；单纯重复点击继续不保证解决现有固定计划。
