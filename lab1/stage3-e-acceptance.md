# 小步 3E 验收与前三阶段总结

## 完成内容

3E 已实现持久调度器和手机管理界面。调度器按有界批次执行只读增量采集、三态分类和邮件任务分派，保存暂停、退避、最近扫描与最近成功状态。已处理且来源和策略未变化的分类不会再次进入分派，等待用户输入的任务不会占用新邮件额度，空闲周期不会调用模型。

网页显示扫描状态、当前代积压、分类统计和收件处理列表；支持查看分类理由、打开关联任务、纠正单封邮件分类，以及暂停、恢复和手动扫描。分类纠正仍只作用于当前邮件，不形成长期偏好。所有发送继续要求用户核对并确认冻结版本。

`no_reply` 邮件（含人工纠正结果）可独立标记为已处理并从默认队列隐藏，原分类、理由和纠正历史保持不变；已处理区域支持恢复。其他分类不能直接隐藏。隐藏记录绑定当前分类版本，分类变化后邮件会自动重新出现。

存在 SMTP `accepted` 记录的已完成回复任务可归档，并从默认任务列表及自动邮件队列隐藏；归档保留完整发送审计，恢复后方可继续操作。无需回复的“已处理”和已发送任务的“已归档”分开保存、分开展示，两个历史列表都只返回最近加入的 10 条，完整历史不删除。

提供 `systemd/gse-mail-scheduler.service` 与 `systemd/gse-mail-web.service` 用户服务模板。模板没有自动安装或启用，避免在未核对运行环境时改变用户会话启动项。

## 验收

- 调度器测试覆盖有界积压清空、旧分类不占额度、空闲零模型调用、暂停持久化、暂停时手动单轮不自动恢复，以及队列摘要不返回邮件正文。
- 网页接口测试覆盖认证、跨站拒绝、状态和队列读取、暂停、恢复、手动扫描及分类纠正。
- 3D 继续覆盖新往来、旧预览失效、用户编辑保留和跨任务结果不明保护。
- 阶段三完成时全量回归为 169 项；增加“已处理并隐藏”和“已发送任务归档”功能后，全量回归共 **176 项通过**。Python 编译、前端 JavaScript 语法、补丁格式检查和两个 systemd 用户服务模板校验通过。
- 真实邮箱联网首轮将游标推进到 UID 211，2 封 ready 邮件完成分类和分派，分类均为 `no_reply`；没有创建或发送邮件。紧接着再次执行，结果为 `classified=0`、`dispatched=0`，验证稳定空闲状态不会重复调用模型或反复分派。
- 受限网络下的首次探测进入 `retry_wait`，没有误判或发送；修复了调度汇总曾把监控 `retry_wait` 显示为 active 的问题。联网复验后监控和调度均恢复为 active，错误清空。

## 前三阶段完整性

按项目文档约定的范围，阶段一的个人资料检索与补充恢复、阶段二的单封邮件人工闭环、阶段三的持续采集分类与安全任务编排均已实现。系统能够作为单账号、单机的自动邮件助手长期运行：自动收信、分类、准备草稿和等待用户处理；不会自动确认或发送。

“可长期运行”不等于不依赖运行环境。主机必须保持开机联网，WSL/systemd 和局域网转发需要可用；当前机器已安装并启用两个用户服务。`restart_and_verify.sh` 可在功能更新后同步模板、重启并验证服务。ehall、原生手机应用、跨设备公网部署及从修改中学习长期偏好属于后续阶段。
