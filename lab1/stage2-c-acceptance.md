# 2C：手机网页与草稿编辑

日期：2026-09-15。

结果：73 项 Python 测试全部通过（原有 64 项，新增 9 项），JavaScript 语法检查通过。真实手机浏览器与网络访问待验收。

## 实现

采用 Python 标准库 ThreadingHTTPServer 与无第三方依赖的 HTML/CSS/JavaScript。响应式页面包含访问口令登录、最近收件列表与只读保存、已有快照选择、目标和历史选择、任务列表与进度、事实补充、保存范围与冲突确认、本次决定、草稿编辑、历史版本与来源查看。

访问口令首次启动时写入被忽略的 `data/web-token.txt`，权限由 077 umask 约束。页面仅将口令放在当前标签页 sessionStorage，每次 API 请求携带 Authorization；不使用登录 Cookie，不允许跨站 Origin，不开放 CORS。静态页面不含私人数据。邮件内容通过 textContent/表单 value 显示，不插入原始 HTML。

编辑提交携带草稿版本。服务端在任务锁内比较版本与来源状态，旧版本返回 HTTP 409，过时草稿也拒绝保存。成功保存新增用户版本，保留原草稿和生成时来源；用户修改不自动成为新个人事实或经过核验的证据。模型不会在保存编辑时改写内容。

页面遇到编辑冲突保留输入，可查看服务器最新版本，复制合并后重新打开任务提交。离开未保存编辑时浏览器会提示；未保存输入不写入服务端，强制关闭页面可能丢失。已提交内容持久化到 SQLite，关闭页面或服务器重启后可读取。

API 操作由请求线程执行。浏览器断开不主动取消后台任务，父子状态和草稿仍按 2B 持久化；服务器中断后可通过“重新准备 / 继续”恢复已保存任务。请求若尚未接受补充就中断，需要查看状态后重交。网络错误不能当作“未保存”，应先重新读取任务。

## 自动验证

运行全套 Python 测试及 `node --check lab1/web/app.js`。新增测试覆盖：

- 用户编辑新增版本、保留历史、旧版本不能覆盖；资料变更拒绝编辑；主题换行注入拒绝。
- HTTP 未认证 401、跨站 Origin 403、正常认证可读取。
- HTTP 编辑成功、旧版本 409、新连接可读取已保存内容。
- 服务停止后重建服务和应用实例，仍能读到已保存版本。
- HTTP 缺失请求展示、临时事实补充、用户决定与草稿生成完整衔接。
- 快照选择、非法快照路径拒绝、无发送接口、静态资源和错误输入处理。

测试使用虚构邮件、隔离资料和临时数据库；HTTP 仅在本机随机端口运行，结束后关闭。没有调用真实 API、收发真实邮件或改变真实个人资料。

## 当前验收边界

本环境没有 Playwright/Puppeteer 或可调用浏览器工具，尚未完成浏览器实际点击、截图、真实手机触控和局域网连通性验证。移动端样式已实现，但不把接口测试当作真机验收。首次使用时按 README 启动，在手机核对登录、资料输入、草稿编辑、刷新和双页面冲突。

本阶段只提供局域网 HTTP 原型，访问口令与内容没有传输加密；仅在可信网络使用，不应直接暴露公网。默认只监听 127.0.0.1，监听其他地址需显式参数。未配置系统服务、端口转发或防火墙；运行于 WSL 时手机能否直连取决于现有网络可达性。

没有自动发送、附件上传、编辑内容经验总结。发送入口属于 2D。刷新列表只读取状态，不调用模型；需要继续任务时主动选择“重新准备 / 继续”。当前不自动轮询覆盖编辑区。
