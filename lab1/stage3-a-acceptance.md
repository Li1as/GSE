# 3A：增量收信与持久采集验收

日期：2026-09-15。结论：3A 已实现，23 项新增测试及前两阶段回归合计 **130 项通过**；真实 IMAP 隔离验收 **11 项检查通过**。第三阶段整体设计见 [stage3-design.md](stage3-design.md)，启动与恢复命令见 [README.md](README.md)。3B—3E 尚未实现。

## 交付

- `mail_reader.py` 增加 UIDNEXT 与有界 UID 搜索，过滤越界/重复结果、拒绝非法返回；复用只读 SELECT、BODY.PEEK 和 MIME 解析。
- `mail_inbox.py` 保存账号端点/文件夹扫描状态、UID 代标识与持久采集记录。发现记录与扫描边界同事务提交。
- `mail_monitor.py` 提供 once/run/status/list/retry。默认首次从当前边界开始，显式支持现存邮件扫描、历史区间补录、认证恢复与新代确认。单机锁防止并发采集，崩溃后恢复待办和完整快照。
- 采集状态与未来分类分开；ready 仅表示采集完成。错误、超限、解析失败、重试耗尽保留记录供人工处理，单条异常不丢弃后面的待办。
- 状态、快照和验收报告均在 data/ 中被 Git 忽略；队列文件权限 600，快照复用现有私有权限。

## 边界

- 本轮没有制造真实新邮件到达，也没有修改服务器 UIDVALIDITY；这两类逻辑由合成场景验证。真实环境验证的是现有样本的增量接口、补录、持久恢复和只读行为。
- 单条无法读取的邮件最多自动尝试三次，随后需查看/显式重试；服务器已删除的正文无法恢复。
- UID 数值范围、单轮采集数量有上限；单封网络调用仍使用现有超时。第一版单机、INBOX、轮询，不实现 IDLE 或多机协调。
- 旧代记录保留在数据库，当前代统计单独返回；代变更须人工核对，未实现自动跨代去重或历史合并。
- 采集目录尚未接入网页业务任务入口；分类、用户改判、自动拟稿与跨任务发送保护属于 3B—3E。
- 未安装或启动常驻监控，未调用模型，未发送邮件，未提交 Git。
