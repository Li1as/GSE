## 补充修复：waiting_input 中的来源限定

2026-09-15 后续真实操作发现，同一来源限定也可能被模型放入 missing，导致此前仅处理 needs_review 的复核被跳过。

- 复核入口现覆盖已有证据答案的 waiting_input；对 missing 逐项分类为真正必需、来源说明、范围外要求或已有证据覆盖。
- 程序校验所有原缺失项恰好覆盖一次，要求逐项理由；将缺失判为来源说明或已覆盖时，必须引用现有证据。真正必需项不能在 blocking=false 时被放行。
- 混合缺失只解除不需要的部分，剩余项继续等待。没有证据答案的缺失查询仍保持原补充流程。
- 复核缓存绑定子任务、用户目标、决定和查询字段，并升级策略版本；旧复核不能直接用于变化后的任务。

## 修改

1. 已接受的长期补充在续答时直接作为当前文件证据提供，避免只归档、却未检索到。仍读取当前 Markdown 内容，不复活被修改或删除的旧文本。临时补充继续限定于当前任务；同一邮件重新规划后可携带本邮件旧子任务的补充，其他邮件不可访问。
2. 决定类型区分 scope 与 choice。范围尚未明确时暂缓事实查询；范围回复或语义判断影响查询计划时触发重新规划。保留旧计划、子任务和请求，新计划生成新子任务，已回答的决定保留。旧计划中不再需要的未答问题不继续阻塞。
3. 重新规划同时读取当前已接受补充，以理解本科/后续学位等字段语境。已知字段仍须进入事实查询清单，保证最终草稿获得完整来源。
4. blocker 区分当前阻碍与解除方式，一般限制进入 notes。询问对方测试内容不依赖事先知道测试内容；请求对方发附件不依赖分析已有附件。真实必须理解附件时仍阻塞。
5. 个人查询允许单独返回 notes；只将影响本次字段的实际矛盾放 conflicts，保留真正的冲突处理。禁止将检索中发现的其他经历自动扩展成必填信息。
   对“有答案但只有来源限定”的 needs_review，邮件层增加按用户实际目标进行的复核，保留原资料查询结果与复核理由；可用限定措辞回答时才用于草稿。模型自拟查询中的“当前”不等于用户明确要求当前身份认证。真实冲突继续阻塞，引用仍须来自既有证据。复核缓存绑定原查询依赖与复核策略版本。
6. 非预期异常记录 stage 与 exception_type。模型调用中的 OSError 不再伪装为资料文件错误；不记录可能包含凭据的原始异常内容。
7. 父任务记录每个未完成子任务的独立问题，网页展示子任务错误、来源说明和解除阻塞的方法，提供重新规划与单项查询重试。

## 使用

已有网页任务可点击“按当前决定重新规划”；旧版计划在显式继续时也会升级。更新页面后如果没有新按钮，需要确保服务器已重启加载新版代码。

```bash
python3 lab1/mail_tasks.py replan <邮件任务编号>
```

重规划不会把历史 task 范围补充变为长期资料。新旧查询的事实结果均保留来源；原始档案不改写。现阶段模型仍负责语义分类，不能宣称以程序校验证明任意自然语言任务的字段完整性。

## 回归方法

- 全套测试新增长期补充直接入上下文、范围变更重规划、未明确范围时暂缓查询、同邮件补充继承与历史保留、来源 notes 不阻塞、错误分类、同时存在阻塞和失败的展示检查。
- `live_real_task_regression.py` 使用 SQLite backup 和个人 Markdown 副本，重定向副本中的数据路径。调用真实 API，既检查任务状态，也检查实际草稿包含年级、本科毕业时间、GPA、编程语言及请求附件，不包含额外博士毕业时间。
- 原真实任务、请求和个人资料不由回归脚本修改；结果保存于 `data/real-regression/<运行编号>/`。
- 回归期间先后发现规划上下文缺少已接受补充，以及已知字段被错误省略；对应修正后再次验证。早期运行的状态通过不等同最终内容验收通过。
