新增故障场景：

| 场景 | 结果 |
| --- | --- |
| 模型 API 超时后继续原任务 | 保留任务编号，恢复后生成草稿 |
| 邮箱认证失效 | 返回明确不可用响应，现有任务与补充请求保留 |
| 浏览器在模型处理期间断开 | 后台继续并保存结果，新连接可读取 |
| 服务器停止后重建服务及应用实例 | 已保存任务、编辑版本和发送记录仍存在 |
| SMTP 已返回接收，但最终本地回执写入失败 | 重启后变为 unknown，不再次调用传输器 |
| 已保存冻结内容被篡改 | 归档审计拒绝通过内容指纹与字段校验 |

此前用例继续覆盖确认前后附件变化、资料更新、两个页面编辑冲突、发送并发、收件人部分拒收、DATA 超时、未确认拒发和真实缺失资料保留。

## 真实邮件核对与归档

用户已明确报告真实测试能正确发送。当前对应记录为 `<本地记录编号>`：status=accepted、attempts=1、stage=data、smtp_code=250。

新增 `mail_delivery_audit.py` 对冻结 MIME 和预览内容作独立核对：确认时刻、尝试次数、内容指纹、字节哈希、Message-ID、From/To/Cc、Bcc 不进入邮件头、主题、正文与附件均匹配，**13 项检查全部通过**。发送时 SQLite 已自动保留冻结字节和回执；本工具另行导出便于人工查看的文件。

```bash
# 只检查和导出本地已接收记录，不访问邮箱、不调用模型
python3 lab1/mail_delivery_audit.py
# 显式选择记录，并只读核对已发送目录
python3 lab1/mail_delivery_audit.py --send-id <发送记录编号> --check-sent-folder
```

`--user-confirmed-success` 仅在用户确实报告该次实际发送成功时使用，记录该人工证据，不能代替程序对收件端投递的独立证明。

本次归档位于 `data/mail-archive/<本地记录编号>/`：

- `message.eml`：实际提交给 SMTP 的冻结字节。
- `receipt.json`：具体版本、收件人、确认与发送结果。
- `audit.json`：核对结果、用户成功反馈标记及已发送目录查询结果。

这些文件在 Git 忽略范围，文件权限 600、归档目录权限 700。核对过程没有再次发信，没有移动、删除或追加服务器邮件。

## 保留边界

1. 本次两次查询 Sent Messages 均未找到同一 Message-ID，因此**未观察到该次 SMTP 邮件的自动已发送副本**；不据此推断发送失败，也不声称已证明腾讯所有配置下都不会自动保存。当前以本地冻结内容和回执归档为依据，没有盲目 APPEND。若需要邮箱网页中必有副本，应作为后续明确功能单独实现与验收。
2. SMTP 接收、用户确认成功与收件端独立投递回执是不同证据。没有实现已读追踪。结果不明继续保留 unknown，核查后也不会自动重发。
3. 当前是单机、单用户、可信局域网 HTTP 原型。未实现公网部署、HTTPS、跨机器锁或自动后台服务安装。
4. 往来使用显式选择的有限历史，不保证任意邮箱中的完整会话重建。支持附件传输和校验，不自动理解附件内容。
5. 浏览器页面已有真实使用反馈和 HTTP 自动测试，但没有覆盖所有手机型号或进行完整浏览器自动化视觉验收。
6. 模型对范围、来源限定和语义的判断仍可能有误；已有结构、引用、版本约束和真实问题回归，最终发送仍需用户审阅确认。修复并不意味着任意自然语言任务都能一次成功。
