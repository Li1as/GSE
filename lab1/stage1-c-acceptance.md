# 第一阶段小步 C 验收记录

日期：2026-09-14。实现位于 [assistant.py](assistant.py)，用法见 [README.md](README.md)。

## 已实现

- 缺失信息生成 SQLite 请求记录和 `data/requests/<请求编号>.md` 文件，包含任务、用途、已检索范围和回复区域。
- `answer_request(request_id, text, scope, confirm_conflict=False)` 接受文本；CLI 支持直接文本、UTF-8 Markdown／纯文本文件，以及请求文件的 reply 标记区域。
- 模型检查相关性、字段对应与冲突，程序校验摘录必须来自用户回复。无关回复不归档，冲突先等待用户明确确认。
- 回复明确选择 task 或 personal。临时回答只成为当前任务证据；长期信息独立归档，保留用户原文、请求上下文、时间和来源。
- 同一任务编号继续执行。部分回答后仍有缺失则生成新的后续请求，不把未回答项直接标记完成。
- 相同回复重复提交去重；接受后续答失败可以原样重试。原资料不覆盖。

| 场景 | 验收结果 |
| --- | --- |
| 请求生成和离线查询 | 请求文件与数据库包含正确任务和缺失信息 |
| 无关回复 | 原任务仍等待、请求仍 pending、无长期归档 |
| 临时回答 | 原任务续答并引用临时证据，独立新任务仍缺失 |
| 长期回答 | 生成一份独立 Markdown，新实例可检索，原资料不变 |
| 重复提交 | 不重复归档、不重复完成查询；已关闭请求拒绝不同回复 |
| 部分回答 | 接受已有部分，剩余问题生成后续请求 |
| 冲突确认 | 默认暂停，明确确认后才接受 |
| 伪造摘录 | 模型返回非用户原文片段时拒绝归档 |
| 校验 API 超时 | 请求保持 pending，不产生补充文件 |
| 接受后续答失败 | 原样重试可继续，不增加第二份补充 |
| Markdown 与输入校验 | 回复区域可提取，空文本和非法范围拒绝 |
| 简短回答 | 字段问题与原文在同一可检索片段中保留，防止丢失回答语境 |
