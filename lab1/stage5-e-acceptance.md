# 5E 验收及第五阶段总结

## 完成内容

- `experience/workflows/mail-reply.md` 固化邮件长期运行入口、状态序列、经验审核、安全边界、故障恢复和验收方法。
- `test_stage5_e.py` 使用隔离 IMAP、模型和 SMTP 替身串联规则发布、分类、任务规划、拟稿、用户编辑、草稿经验提议、冻结确认、发送与归档。
- 同一邮件重复扫描、分类和分派不会增加来源、任务或发送记录；进程重建后仍可读取草稿历史、归档状态、SMTP 接收记录和经验应用审计。
- 第二个合成 ehall 适配器复用 URL 识别、结构化检查、决定规范化、试填、回读、后果展示、精确确认、单次提交和只读核对边界，不增加生产事务。

## 自动验收

```bash
PYTHONPATH=lab1 python3 -m unittest -v lab1.test_stage5_e
PYTHONPATH=lab1 python3 -m unittest discover -s lab1 -p 'test_*.py'
```

端到端测试不连接外部邮箱、SMTP、模型或 ehall，不产生真实副作用。真实服务部署仍由 `restart_and_verify.sh` 检查语法、测试、服务状态、未授权访问及受保护接口。

## 完整性结论

按阶段一至五的既定范围，Lab1 已形成可长期运行的单用户个人助手：本地个人资料具有来源和更新边界；邮件具备只读采集、分类、任务编排、资料补充、草稿版本、显式确认、保守发送及归档；ehall 具备 URL 驱动的单项退课适配器、回读、冻结确认、一次执行和结果不明保护；经验规则具备显式提议、人工审核、连续版本、跨会话应用和逐字审计。

结论仅适用于当前设计边界。它不是通用浏览器 Agent，不自动发现 ehall 事项，不自动发送或提交，不保证 SMTP 最终投递，也不适合直接暴露到公网。新增真实 ehall 事务必须编写并验收独立适配器；长期运行仍依赖本机 systemd、邮箱/模型配置、网络和人工处理 `needs_review`、`unknown` 等状态。
