日期：2026-09-15。结论：3B 已实现；16 项新增分类测试通过，全部 146 项回归测试通过。真实 API 对用户提供的测试邮件快照完成分类，10 项隔离检查全部通过。3C 的自动业务任务关联及 3E 的手机分类界面尚未实现。

## 交付与边界

- `mail_classifier.py` 持久保存分类状态、有限重试、来源版本、模型原判和人工纠正历史；once/run 可与 3A 采集串联。
- 三类结果为 reply_required、no_reply、user_review。模型成功输出后才可能出现 no_reply，API、协议和来源错误使用独立状态。
- 模型只接收当前邮件和最多四封由回复头关联的已采集往来，不接收个人资料库、邮箱凭据或附件字节。历史明确标记为不完整。
- 行动依据必须逐字来自当前正文；回复类必须有建议目标，判断类必须有具体问题。分类不替用户作决定。
- 已完成且来源/策略未变的记录不占处理额度、不再次调用模型。来源或策略变化进入 needs_review。
- 人工纠正不调用模型，保留模型原判和历史，不创建邮件任务、不生成长期偏好。CLI 是本阶段入口；手机端留在 3E。

## 自动测试

新增 16 项测试覆盖：

- 三类结果持久化、重启可查及完成结果幂等。
- 当前邮件进入模型上下文，个人资料配置和密钥不进入上下文。
- 行动引用必须来自当前正文，类别专属字段必须完整。
- API 超时、无效 JSON、协议错误不会误记为 no_reply；三次预算与指定 UID 人工重试。
- 模型原判、人工纠正和历史同时保留；纠正不调用模型或创建 mail_tasks。
- 回复头相关历史进入上下文，无关邮件被排除，历史明确不完整。
- 邮件中的提示注入只作为数据；分类不会执行指令或产生发送操作。
- 模型调用后和状态保存后的两个中断边界可恢复；已保存结果不重复调用。
- 快照内容变化、快照损坏进入人工核对，同时不会阻塞后续邮件。
- `needs_review` 不自动重跑；人工 retry 精确处理指定 UID，不被更早记录抢占。

## 真实 API 隔离验收

执行 `python3 lab1/live_classifier_acceptance.py`。脚本复制 3A 刚采集的测试邮件快照到独立 `data/classifier-acceptance/<运行编号>/`，不会修改生产分类状态，也不访问 IMAP 或 SMTP。

真实模型将该邮件分类为 no_reply、置信度 high；理由是当前发件人仅确认收到并说明测试性质，没有提出新的邮件回复要求。该判断与当前邮件新增内容一致。检查确认：

1. 分类状态、类别和理由有效。
2. 分类绑定当前 EML 哈希，模型原判完整保留。
3. 第二轮不再次调用模型；实际模型调用一次。
4. 模型上下文不包含个人资料配置或 API 密钥。
5. 未创建 mail_tasks 或 mail_sends 表，发送次数为零。
6. 隔离环境人工改判不调用模型，保留原判和一条纠正历史。
7. 新实例读取后仍保留纠正结果。

验收输出不包含邮件正文、账号或凭据；完整结果及隔离数据库受 Git 忽略。

## 保留限制

- 真实验收仅覆盖一封不需回复的测试邮件。reply_required 和 user_review 使用合成邮件验证，后续遇到真实样本时继续积累案例。
- 语义分类依赖模型，结构和引用校验不能证明每次判断都正确；因此无需回复记录保持可见并可纠正。
- 当前不自动从分类创建邮件任务，不会自动回复；该关联和跨入口去重属于 3C。
- 当前网页尚未展示分类或提供手机纠正，属于 3E。持续服务仍需用户显式运行，没有安装自启动服务。
- 本轮没有发送邮件、修改真实分类状态或提交 Git。
