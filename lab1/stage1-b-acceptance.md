# 第一阶段小步 B 验收记录

日期：2026-09-14。实现：[assistant.py](assistant.py)。运行方式见 [README.md](README.md)。

## 实际交付

- 标准库 Python CLI，以及可复用的 `Assistant.query(text)`、`Assistant.get_task(task_id)`。
- 用户指定 API 的 Chat Completions 接入，模型保持 `gpt-5.6-terra`。服务模型列表包含该标识，实际请求成功。
- 模型通过 JSON 动作使用目录、分类／关键词／别名搜索与证据读取；本地程序不开放 Shell 或任意文件写入。
- Markdown 按段落、完整项目条目和成绩表行分段，表格结果保留表头；支持分页。
- 每条回答引用已读取的片段，并附文件、标题、行号、内容版本和证据原文。
- SQLite 保存任务、搜索轨迹、证据和结果，支持无需 API 的离线任务查询。
- 缺配置、HTTP 错误、超时、异常响应、模型动作错误、无效引用及步骤耗尽分别报错，不伪装成资料缺失。

## 真实 API 验收

命令：`python3 lab1/live_acceptance.py`

使用当前资料与指定服务，最多两项查询并发。最终六项均通过，完整任务和证据保存在被 Git 忽略的 `data/tasks.sqlite`，结构化摘要在 `data/live-acceptance.json`。

| 案例 | 实际结果 | 状态 |
| --- | --- | --- |
| 数据库课程不同问法 | 返回正确总评，有课程号和来源 | completed |
| CS61A 别名 | 返回别名对应课程的正确成绩 | completed |
| 篮球多次修读 | 分别返回各学期成绩，引用对应记录 | completed |
| 未提供的护照到期日期 | 未编造日期，返回缺失项 | waiting_input |
| 编译原理评分口径 | 区分项目评分与课程总评；分别引用简历和成绩单 | needs_review |
| 高级程序设计项目日期 | 指出原文日期倒置，要求确认，不猜测正确年份 | waiting_input |

自动检查覆盖关键数值、引用来源、状态和重复记录；另人工阅读了最终六项的答案、缺失项与冲突说明。程序对引用身份的校验不等同于证明所有生成文字均与证据语义一致。

首轮六项中五项通过，CS61A 案例曾因 JSON 无效失败。增加 JSON 输出约束和一次受步骤上限约束的修复重试后，完整复验六项通过；同时补充项目分段回归测试。此结果是本轮样例验收，不代表模型每次输出绝不会失败。
