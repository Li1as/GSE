# 小步 3D 验收记录

## 完成范围

3D 已实现本地往来版本、相关新邮件发现、待核对状态、纳入或忽略更新、用户编辑保留、旧预览失效，以及同一往来跨任务的发送结果不明保护。

关联依据为同一账号下可验证的 Message-ID、In-Reply-To 和 References。主题相同不是关联依据；内容相同但 UID 不同的邮件仍作为不同投递。每个任务最多向模型提供四封历史，历史不完整会明确标记，只有模型计划判定其确实阻止当前目标时才等待补充。

## 自动测试

新增用例覆盖：

- 新回复复用原未完成任务，不再次调用拟稿模型。
- 新回复到达后草稿变为过时，旧发送预览不能确认。
- 忽略无关更新时保留用户正文并生成绑定新往来版本的草稿版本。
- 纳入更新时以最新邮件为回复对象、旧邮件进入历史，用户编辑作为重新拟稿输入。
- 同内容不同 UID 不错误合并。
- 已发送任务后的新回复可以建立后续任务，但同一往来其他任务存在 `unknown` 时不能发送。
- 现有 SMTP、网页、分类、监控及阶段一、二流程无回归。

完整自动回归共 163 项通过。Python 编译、前端 JavaScript 语法及补丁格式检查通过。

## 真实快照隔离验收

使用本地保存的真实连续邮件往来快照，在全新的隔离数据库中执行 11 项检查，全部通过：识别真实线程、保留编辑、旧草稿变为过时、旧预览失效、忽略后生成当前版本、纳入后切换回复对象并保留历史、将用户编辑交给重新拟稿，以及全程没有发送记录。

私有结果保存在被 Git 忽略的 `data/thread-acceptance/`。验收只读取既有 EML/JSON，没有连接邮箱、改变未读状态、调用 SMTP 或发送邮件。

## 边界

3D 只能检查已经被 3A 扫描并落盘的往来，不能保证尚未扫描到的服务器邮件已参与发送前检查。手机端可以在任务详情中处理已经发现的更新；全局收件分类列表、持续公平调度、积压状态和暂停控制属于 3E。
