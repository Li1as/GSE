# 小步 4A 验收：URL 入口与只读页面探测

## 实现结果

4A 已实现用户 URL 驱动的 ehall 只读探测入口。程序只接受 HTTPS 及精确配置的任务域名，保留 SPA fragment 和 ehall 的实际查询参数，并在命令输出中删除查询参数和 fragment，避免暴露入口令牌。浏览器跳转到未配置域名时中止。

`ehall_browser.py check-url` 仅做离线 URL 检查；`probe` 使用独立浏览器资料目录，允许登录后识别“我的课表”页面，保存可见文字、控件标签、截图哈希和只读标记。完整 URL、页面文字和截图只保存在被 Git 忽略的 `data/ehall/`。程序没有事务字段填写或退课提交接口。

根据 2026-09-16 的更正，账号密码登录实现已删除。程序在统一认证页只截取 `#qr_img` 对应二维码，临时保存到 `data/ehall/login/qr.png`，输出不含二维码内容，只提示本地路径并等待人工扫码。二维码刷新时原子替换，成功、超时或失败后删除；锁文件阻止两个任务竞争同一二维码位置。程序不处理滑块或验证码。

## 自动验证

新增 8 项离线测试，覆盖：

- 允许域名、HTTPS、端口、URL 内嵌凭据和相似恶意域名。
- HTML `&amp;` 与真实 `amp_sec_version_` 参数的区别。
- `#/xskcb` SPA 路由保留和公开摘要脱敏。
- “我的课表”页面身份及页面标识变化。
- 精确域名配置与本地配置权限。

完整离线回归共 184 项测试通过，前三阶段行为未受影响。

## 真实站点验证

此前使用账号密码的尝试已被本次决策废弃。用户提供的“我的课表” URL 能正确跳转到南京大学统一身份认证页，真实页面中的二维码元素稳定标识为 `#qr_img`，尺寸为 180×180，可进行元素级截图。4A 只验证扫码后返回目标页面，不填写事务字段，也不点击退课或其他业务按钮。

2026-09-16 已完成二维码真实验收：程序把二维码写入约定私有路径，用户扫码确认后，原浏览器会话自动返回用户提供的 URL。页面标题为“我的课表”，适配器识别结果为 `my_timetable`，并保存只读页面文字、截图及匹配的截图 SHA-256。探测结果标记为 `read_only=true`。

扫码成功后 `qr.png` 与 `qr.json` 均已删除；浏览器会话保留在被 Git 忽略的私有 profile 中供有效期内复用。本次未填写任何事务字段，页面探测只观察到一个可操作控件，程序没有点击该控件，也没有发起退课或其他提交。

至此 4A 已在真实站点完成“URL → 认证跳转 → 临时二维码 → 人工扫码 → 返回原 URL → 课表身份识别 → 私有只读证据”的完整验收。

## 后续边界

用户选定的最终事务方向是从“我的课表”页面办理特定课程退课。退课具有明确后果，不能在 4A 实现或试点提交。后续阶段必须先完成具体课程选择追问、页面字段适配、冻结预览、用户确认、单次提交、结果不明保护和外部结果核对，之后才能进行真实退课验收。
