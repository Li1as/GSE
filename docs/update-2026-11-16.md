| [9：DeepSeek Harness](09-deepseek-harness.md) | 从小型 Agent 循环到插件框架；Session 事件及其投影、Agent 执行、界面 slots、事件协同；大型应用接入与 GenUI。 | 将前面的架构思想落实到可扩展 Agent 运行框架，强调插件之间的共同语义和协作边界。 |
| [10：软件的演化](10-software-evolution.md) | 架构如何随需求演变；从提交历史学习 RFC/ADR、原子变更、worktree、录制回放和发布验证；从事故、评审中沉淀规则。 | 不只看一个版本能否工作，还看下一次修改是否容易；“通过检查”也不自动等于设计有品味。 |

总体上，课程从“怎样使用 Agent 写软件”，推进到“怎样设计能持续演化、能被验证的软件与 Agent 环境”。人的核心工作仍是提出问题、选择抽象、明确验收条件，并把纠正变成下一次可复用的反馈机制。

## Lab2 新要求

[Lab2 原页面](https://jyywiki.cn/GSE/2026/lab2.md)延续 Lab1 的个人数据库：增加一个 `effort` 选项，控制计算预算，通过多方向探索、查证、评估和修改改善结果。

可将任务的资料、候选解和未解决问题组织成求解状态，从同一状态尝试不同提示词或方法，在预算耗尽前保留最好的候选结果。还要关注资料检索与上下文选择；向量数据库只是可尝试的工具，不是强制要求。

讲义建议用真实任务比较“直接求解、低 effort、高 effort”：固定输入资料与基础模型，提前确定评价标准，同时记录质量、耗时和 token 消耗；对开放答案可匿名打乱顺序比较，并核查关键结论。完整评测不强制要求，首先积累能看到改善或退步的案例。未完成 Lab1 也可以从能检索资料、读写文件的 Agent 开始。

对当前项目的含义：可在现有个人资料检索与任务系统上扩展独立的研究任务和预算控制，不需要为了 Lab2 把所有查询都改成多轮搜索，也不必为少量个人事实强制增加向量索引。这是结合项目的实现建议，不是课程新增的硬性要求。
